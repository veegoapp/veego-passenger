Phase 6 — Migrate Ride Recovery Ownership to ActiveSession

Use the attached ActiveSession Mobile Integration Contract as the only source of truth for backend session behavior.

Goal:
Move remaining ride recovery responsibility from service-specific code into ActiveSessionContext.

Scope ONLY:
- src/hooks/car/useRide.ts
- src/session/activeRideSelectors.ts (if needed)
- related ride recovery code paths

Do NOT modify:
- Shuttle screens
- BookingContext
- ticket.tsx
- trip-detail.tsx
- navigation
- backend code

Tasks:

1. Audit all recovery responsibilities inside useRide.ts.

Identify:
- GET /rides/active usage
- GET /rides/:id usage
- socket reconnect recovery
- local state that duplicates ActiveSession fields

2. Remove GET /rides/active as a ride recovery mechanism.

Rules:
- ActiveSessionContext is now the only source for discovering an active ride.
- Do not fallback to /rides/active after a successful ActiveSession response.
- Only keep legacy code if there is a proven non-recovery use case.

3. Migrate reconnect recovery.

Current behavior:
- useRide refreshes ride details after socket reconnect.

Change:
- ActiveSessionContext/session:snapshot should become the recovery source after reconnect.
- Keep only ride-specific socket listeners required for live UI updates.
- Do not duplicate full ride synchronization in useRide.

4. Preserve UI compatibility.

CarServiceScreen and existing consumers must continue receiving the same ride state shape.

Do not rewrite screens.
Adapt ActiveSession data into the existing RideState shape if required.

5. Add safety checks:

Do not overwrite ride state when:
- ActiveSession belongs to another service type.
- Session rideId does not match current ride.
- Backend returns no active session.
- Terminal state was already handled.

6. Verify behavior:

Test mentally/code review these cases:

- Cold start with active car ride.
- Cold start with no session.
- Socket reconnect during active ride.
- Foreground resume during active ride.
- ActiveSession becomes null after completion.
- Scooter and Delivery do not leak into Car state.

Before changing files:
Provide a short audit of current duplicate recovery logic.

After changes provide:
- Files changed.
- Recovery flow before/after.
- Remaining old recovery code and why it remains.
- TypeScript result.

Do not make assumptions about backend fields. Use only the attached contract.
