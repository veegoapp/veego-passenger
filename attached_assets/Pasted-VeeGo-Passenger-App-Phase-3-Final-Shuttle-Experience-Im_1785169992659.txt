VeeGo Passenger App — Phase 3 Final Shuttle Experience Improvements

Context:
Phases 1 and 2 are already completed successfully.

DO NOT modify or break:
- Car / Scooter / Delivery trip tracking logic from Phase 1.
- PassengerTrackingMap camera improvements from Phase 2.
- Existing route switching logic:
  driver_arriving → driver to pickup
  trip_started → driver to dropoff
- Existing recenter button and user pan handling.

This phase is ONLY for Shuttle passenger experience improvements.

Goal:
Improve the shuttle live tracking experience so the passenger sees only the relevant part of the shuttle journey.

Important business logic:
A shuttle is a fixed route made of stations from backend.

Before passenger boards:
- Passenger should see the shuttle moving along the route.
- Passenger should see stations from the current shuttle position until ONLY their own boarding station.
- Do NOT show stations after the passenger's boarding station because they are irrelevant before pickup.

After passenger boards:
- Passenger should see only the remaining stations after their current boarding station.
- Completed stations behind the passenger should disappear.
- The route should represent the remaining journey only.

Files allowed to modify:
ONLY:
- app/trip-detail.tsx
- components/shared/PassengerTrackingMap.native.tsx

Do not modify backend.
Do not modify sockets.
Do not modify Car/Scooter/Delivery screens.

Implementation requirements:

====================================================
1) Shuttle driver location initial seeding
====================================================

Current issue:
trip-detail.tsx waits only for:
shuttle:driver:location socket event.

This can leave the map without a driver marker after opening the screen.

Fix:
Use existing ActiveSessionContext shuttle session data.

When shuttle trip screen loads:
- If session contains:
  trip.driver.currentLatitude
  trip.driver.currentLongitude

Initialize driverLocation immediately.

Socket updates should continue replacing this value normally.

Do not create a new API.

====================================================
2) Shuttle station filtering logic
====================================================

Add clear passenger-aware station filtering.

Inputs already available:
- stations list
- passengerStationId
- station progress status
- trip status
- boarding state

Create derived stations:

Before boarding:
Show:
- current active station
- upcoming stations
- passenger boarding station

Hide:
- stations after passenger boarding station.

After boarding:
Show:
- stations after passenger boarding station only.

Hide:
- completed stations before passenger location.

Keep station markers behavior intact:
- Do not remove station status colors.
- Do not break station arrival events.

====================================================
3) Shuttle route polyline behavior
====================================================

Current behavior:
Passenger may see stations without a meaningful route before movement.

Improve:

Before trip starts:
If stations exist and driver location is unavailable:
- Draw static route through visible stations.

When driver location becomes available:
- Use road route from:
  driver current location
  through visible remaining stations
  until passenger relevant target station.

After boarding:
- Route should update to only remaining stations.

Do not affect car/scooter/delivery route fetching.
