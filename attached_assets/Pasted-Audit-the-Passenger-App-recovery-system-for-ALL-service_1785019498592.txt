Audit the Passenger App recovery system for ALL services.

Services included:
- Car
- Scooter
- Shuttle
- Delivery

Goal:
Verify that any active service/order/trip always restores to the exact same state after any interruption.

Do not modify any code.
Only investigate and report.

Check every service flow separately.

==================================================
1. Network interruption
==================================================

For each service:
- Car
- Scooter
- Shuttle
- Delivery

Check what happens if internet disconnects during an active operation:

Examples:
- searching for driver
- driver assigned
- driver arriving
- trip started
- shuttle active trip
- delivery in progress

Verify:
- Does the app reconnect automatically?
- Does it refresh the latest state from backend?
- Are socket events recovered?
- Is tracking/location restored?
- Can the user continue normally?

==================================================
2. App close and reopen
==================================================

For each service:

Check what happens if the app is force closed and reopened during every active state.

Verify:
- How does the app detect an active service?
- Which API restores the current state?
- Is the previous screen restored?
- Are all required data restored?

Examples:
- Active car ride
- Active scooter ride
- Active shuttle booking/trip
- Active delivery order

==================================================
3. Background / foreground
==================================================

Check:
- When app goes to background and returns:
  - Are active states refreshed?
  - Are sockets reconnected?
  - Are tracking updates restored?
  - Is the UI synchronized with backend?

==================================================
4. Backend / socket failure
==================================================

Check scenarios:

- Socket server disconnects and returns.
- Backend temporarily goes offline and returns.

Verify:
- Does the app resync automatically?
- Does it fetch the latest service status?
- Can it recover missed events?
- Can it get stuck on an old screen?

==================================================
5. Data persistence and recovery architecture
==================================================

Audit:

- Active service storage
- AsyncStorage/SecureStore usage
- React state only dependencies
- Startup recovery logic
- API calls during app initialization
- Socket lifecycle handling
- Navigation restoration logic

==================================================
6. Final report format
==================================================

Provide:

1. Recovery flow for each service:
   - Car
   - Scooter
   - Shuttle
   - Delivery

2. Files responsible.

3. What happens in every interruption scenario.

4. Any state that can be lost.

5. Any service that does not recover correctly.

6. Minimal recommended fixes.

Important:
Do not change code.
Do not refactor.
Only investigate.
